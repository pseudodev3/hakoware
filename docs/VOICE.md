# Hakoware Voice Guide

Hakoware sounds **short, specific, slightly mischievous, and never corporate**.

The product should feel like a game between real people, not software explaining itself.

## Core rule

**State first. Action second. Explanation only when needed.**

Prefer `Waiting on them.` over `Your contract partner has not completed their check-in yet.`

Prefer `1 needs attention.` over `You currently have one contract that requires your attention.`

## Length

- States: usually 2–8 words.
- Routine explanations: one short sentence.
- Routine flows: two short sentences maximum.
- Use more detail only when consequences, Aura, destructive actions, security, or ambiguity require it.

## Tone

Hakoware is direct, playful, socially aware, confident, lightly chaotic, and human.

It is not corporate, motivational, overly cute, tutorial-heavy, fake-edgy, or sarcastic toward the user.

Use humor as seasoning, not as the interface.

## Vocabulary

Use the game’s established terms consistently: **Duo, contract, check-in, debt, bankrupt, recovering, Chaos, Aura, Claim, Grudge, Wanted, season, bounty**.

Do not invent synonyms for existing mechanics.

## States

Say what is happening now.

Good:
- `Waiting on them.`
- `You're clear.`
- `Debt starts in 8h.`
- `Bankrupt.`
- `Recovering.`
- `Chaos is live.`
- `Season complete.`

Avoid headings or prose that merely restate the visible UI.

## Actions

Buttons name the action: `Check in`, `Send voice`, `Accept`, `Decline`, `Start contract`, `Claim`, `Post bounty`, `End contract`.

Avoid vague labels like `Proceed`, `Submit`, or `Continue` when the actual action can be named.

## Success

Keep routine success quiet:
- `Check-in counted.`
- `Contract started.`
- `Bounty posted.`
- `Season complete.`
- `You're stable again.`

Do not celebrate every tap.

## Errors

Say what failed and, when useful, what happens next:
- `Voice upload failed. Try again.`
- `That username is taken.`
- `You're too early. Check in again in 3h.`
- `Couldn't sync. Your check-in wasn't counted.`

Avoid `Something went wrong` when a specific failure is known.

## Danger and consequences

High-stakes copy gets **more clarity, not more personality**.

Before ending a contract, spending significant Aura, using Claim or Revenge, resolving bankruptcy, assigning bounty credit, or taking an irreversible action, keep the meaningful consequence explicit.

A joke may sit nearby. It must never hide the consequence.

## Empty states

Keep them brief and useful:
- `No active bounties.`
- `No Grudges yet.`
- `Nothing needs you right now.`
- `No contracts yet. Start one with someone.`

## Mischief

Occasional lines like `They vanished.`, `Things got expensive.`, `Now it's personal.`, or `You survived.` are fine when the game state earns them.

Routine information stays calm. Personality gets louder when the game gets louder.

## Banned patterns

Avoid:
- `This feature allows you to...`
- `Here you can...`
- `Please note that...`
- `In order to...`
- `You currently have...`
- `Successfully completed`
- `Manage your...`
- `View your...`
- `Track your...`
- repeated headings and descriptions that say the same thing

## Final check

Before shipping a line:

1. Can it lose words without losing meaning?
2. Does it expose the current state first?
3. Is the next action obvious?
4. Does it sound like Hakoware rather than SaaS?
5. If it has consequences, are they explicit?

**Short, specific, slightly mischievous. Never corporate. Never over-explain.**
